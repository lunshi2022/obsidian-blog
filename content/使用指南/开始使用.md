这套站点只有一个原则：**你只管在 Obsidian 里写 Markdown，剩下的交给构建脚本。**

## 三步发布

1. 把 `.md` 文件放进 `content/` 目录（可以带子文件夹，目录结构会原样变成侧边栏的目录树）。
2. 在本地双击运行一次构建，看看效果：

```bash
npm run dev
```

浏览器打开 `http://localhost:4321` 就能预览。改完笔记重新跑一次即可。

3. 提交并推送到 GitHub，剩下的交给 Actions：

```bash
git add -A
git commit -m "更新笔记"
git push
```

大约一分钟后，`https://你的用户名.github.io/仓库名/` 就会自动更新。

> [!note] 不需要装任何依赖
> 整个构建脚本只用 Node 内置模块，没有 `node_modules`。`npm install` 都可以跳过。

## 笔记里能写什么

| 语法 | 写法 | 说明 |
| --- | --- | --- |
| 双链 | `[[笔记名]]` | 自动解析成站内链接 |
| 别名双链 | `[[笔记名\|显示文字]]` | 显示文字与目标分开 |
| 标题链接 | `[[笔记名#小标题]]` | 跳到对方页面的某个锚点 |
| 嵌入图片 | `![[图片.png]]` | 图片放 `content/附件/` |
| 嵌入笔记 | `![[笔记名]]` | 渲染成一张卡片，防止递归 |
| 标签 | `#标签` 或 frontmatter | 自动生成标签页 |
| Callout | `> [!tip] 标题` | 支持折叠（`[!tip]-`） |

更细的写法见 [[写作语法速查]]。

## 配置站点

打开根目录的 `site.config.json`，改这几项就够了：

```json
{
  "title": "我的数字花园",
  "description": "这里是一句话介绍",
  "author": "你的名字",
  "siteUrl": "https://你的用户名.github.io/仓库名"
}
```

`siteUrl` 只影响 RSS 里的绝对链接，不填也能正常部署。

## 什么时候需要动手改代码

基本不用。真想改的话：

- 配色和字体：`assets/style.css` 顶部的 CSS 变量，改几个十六进制值就能换一套气质。
- 页面结构：`src/lib/templates.js`。
- 解析规则：`src/lib/markdown.js` 和 `src/lib/obsidian.js`。
