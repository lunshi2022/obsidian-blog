# 数字花园 · Windows 一键部署器（原生 exe）

一个独立可执行文件：双击、填三项、点一下。自动装好 Git 与 Obsidian（**不需要 Node**），建仓库、推代码、开 Pages、装插件。

## 拿到 exe（只需做一次）

```
双击 build.bat  →  生成 GardenDeployer.exe
```

编译用 Windows 自带的编译器（.NET Framework 4.x 是系统组件），**不需要安装任何东西**，几秒钟完成。

编译时会把整个站点模板（`src/`、`content/`、`blog-uploader/`、`.github/` 等）压成 `payload.zip` 嵌进 exe，
所以生成的 exe 是**真正的单文件**：发给别人时只需要这一个文件，不用附带模板文件夹。
首次运行时会把模板解压到 `%TEMP%\garden-payload`，之后再启动直接复用（换了新 exe 会自动重新解压）。

> exe 文件名可以随意改（比如改成「数字花园部署器.exe」），不影响运行。

## 用它

1. 双击 exe → 主窗口立即出现（此时**不提权**，所以不会被 UAC 拦住打不开）
2. 选择**部署位置**（默认 `文档\GardenBlog`）
3. 填**仓库名**（默认 `my-garden`）
4. 粘贴 **GitHub 访问令牌**
   - 下面有个「顺便安装 Node.js」复选框，**不勾也行**（默认不勾）
5. 点「开始部署」→ 这时才询问是否以管理员身份继续（安装 Git / Obsidian 需要）
   - 选「是」：以管理员重启并自动继续
   - 选「否」：普通权限继续，若 Git / Obsidian 已装好也能成功
6. 完成后点「打开站点」

### 关于令牌（PAT）

GitHub 早已不允许用账号密码做 git 操作，也无法用密码建仓，所以需要 Personal Access Token。
点界面上的「去创建令牌」会打开已预填权限的页面：勾 **repo** 和 **workflow**（后者是推送 `.github/workflows/` 必需）。

**有效期怎么选**（下拉框里的选项，以实际页面为准）：

| 选项 | 说明 |
| --- | --- |
| 7 / 30 天 | 太短。30 天是默认值，很容易在你不注意时过期 |
| 60 天 | 比默认稍长，仍然容易忘 |
| **90 天（推荐）** | 够用一整个季度，到期前 GitHub 会发邮件提醒 |
| 自定义 | 可以填更远的日期（上限 1 年），适合确定长期用同一台机器 |
| ~~无有效期~~ | 存在，但**不建议**：令牌泄漏就是永久有效。换一次令牌只要一分钟，不值得拿这个换方便 |

生成后请**立刻复制**（页面刷新后只能重新生成，看不到原文）。

**令牌存在哪**：部署成功后写入 **Windows 凭据管理器**（加密），条目名 `git:https://github.com`。
之后 Obsidian 插件每次推送都用它，不再需要输入。

**过期了会怎样**：

- 插件上传时报 `推送失败：… 401`，网站不再更新
- 部署器在第 1 步校验令牌时就停下（不会等到推送才失败）

**怎么修**（三步）：

1. 点界面上的「去创建令牌」重新生成一个
2. 控制面板 → 凭据管理器 → Windows 凭据 → 删掉 `git:https://github.com`（不删的话旧令牌会被继续使用）
3. 重新打开部署器粘一次；或在插件设置里任意改动触发一次保存，下次推送手工输入新令牌

> 不要用 Fine-grained token：它需要逐个勾选仓库和细粒度权限，建仓 API 对它的支持也有限，本部署器认经典令牌。

## 分发

把编译出来的 exe 传到 GitHub Releases（或任何网盘），别人下载后双击即可用，**不需要仓库、不需要模板文件夹**：

- 站点模板已内嵌在 exe 里，首次运行自动解压到 `%TEMP%\garden-payload`
- 对方机器只需要 Windows 10/11（自带 .NET Framework 4.5+，解压用的 `ZipFile` 在这个版本以上才有）

> 如果你的目标机器可能是 Windows 7 / 8，`ZipFile` 的编码重载可能缺失，那时仍建议附带模板文件夹（老版本会自动优先用文件夹）。

## 为什么 exe 只有 253 KB

常见的安装器/下载器动辄几 MB 到上百 MB，这个 exe 只有约 253 KB，靠的是四件事：

| 手段 | 说明 |
| --- | --- |
| 借用系统自带运行时 | 用 C#/WPF 编译，运行时用 Windows 内置的 .NET Framework —— 对比 Electron 应用要打包整个 Chromium（100–150 MB），我们一个字节的运行时都不带 |
| 零第三方库 | HTTP 用内置 WebClient、JSON 用正则解析、压缩用 `System.IO.Compression`、界面手写 XAML，不引入任何 NuGet 包 |
| 模板压缩内嵌 | 整个博客模板 zip 后塞进 exe 资源，纯文本压缩率极高，只占几十 KB |
| Release 级编译 | `csc /optimize+`，不带调试符号 |

它也和 NSIS/Inno Setup 那类「解压壳」本质不同：壳只负责把文件落盘就退场，而这个 exe 是**自包含、可反复运行的部署工具**（重新部署、检查更新都靠它），不写注册表、不装服务，删掉即卸载。

现实收益：用户 1 秒下载完成；代价是 Windows-only 且依赖 .NET Framework 4.x —— Win10/11 全部自带，目标用户完全覆盖。新增功能（比如多主题）只会让内嵌模板多几百字节，exe 体积几乎不动。

## 六步都做了什么

| 步骤 | 动作 |
| --- | --- |
| 环境检测 | 系统版本、管理员权限、磁盘空间、GitHub 连通性；**立刻校验令牌**并取到真实用户名 |
| 准备部署目录 | 复制站点模板；把 `https://<用户名>.github.io/<仓库>/` 写进 `site.config.json` |
| 安装 Git（Node 可选） | Git 缺失则 `winget` 静默安装（失败则下载官方安装包）；**Node.js 默认不装**，勾了复选框才装 |
| 构建站点 | 有 Node 时先本地构建一次（提前发现错误）；没有则跳过，由云端构建 |
| 创建仓库并推送 | GitHub API 建仓 → `git push` → API 把 Pages 发布源设为 GitHub Actions → 存凭据 |
| 安装 Obsidian 与插件 | 缺则安装；插件装入笔记库、预配置上传路径、自动启用、生成一篇示例笔记 |

笔记库就是部署目录本身（`content/` 是笔记目录），一个文件夹同时给 Obsidian 和构建脚本用。

> **首次使用不需要在 Obsidian 里「创建仓库」**：部署器会在最后一步把本机已安装的 Obsidian 直接指向这个目录打开并自动登记。如果没自动弹出，手动打开 Obsidian →「打开文件夹作为仓库」→ 选择部署目录即可，不要点「创建新仓库」（否则会建一个空的、看不到笔记和插件的仓库）。
>
> 早已装过 Obsidian、也已有别的仓库也没关系：博客仓库 = 部署目录，是一个独立文件夹，与你的现有仓库互不干扰；插件只装进博客这个目录，原有仓库原样保留，部署器只是把博客目录登记为「又一个已知仓库」。若部署时 Obsidian 正开着，部署器不会强行弹新窗口，会提示你手动「打开文件夹作为仓库」选择部署目录。

## 卸载与恢复

**先说结论：不需要装 Node.js，卸载这些工具也不会删你的笔记。**
笔记就是部署目录里的普通 `.md` 文件，卸载程序只删自己的 `Program Files` 目录；
已经发布出去的网站托管在 GitHub 服务器上，和你本机装了什么完全无关。

### Node.js 不用装

站点由 GitHub Actions 在每次推送后构建（`node src/build.js` 跑在 GitHub 的服务器上），
所以本机没有 Node 也能正常发布。部署器默认**不安装 Node**：界面上有个「顺便安装 Node.js」复选框，
勾了才会装。本机已有 Node 时不管勾没勾都会用它做一次本地构建，好处是推送前就能发现渲染错误。

| 工具 | 部署器会装吗 | 笔记安全 | 没有它会怎样 |
| --- | --- | --- | --- |
| **Node.js** | ❌ 不装（可选） | ✅ | 无影响，云端构建 |
| **Git** | ✅ 缺失时安装 | — | **无法推送**，笔记发不出去 |
| **Obsidian** | ✅ 缺失时安装 | ✅ | 无法编辑与一键上传 |

### Git 必须留着

Git 是唯一的发布通道，卸了就推不上去。插件的降级行为（已内建）：

- 缺 Node → 跳过本地构建并继续推送，提示「推送后 GitHub 会自动构建发布」
- 缺 Git → 明确报「未检测到 Git，无法推送（笔记已在本地复制完成）」，不会静默失败

### 卸载方式

```
设置 → 应用 → 已安装的应用 → 找到 Git / Obsidian（以及你自己装过的 Node.js）→ 卸载
```

或命令行（winget 装的用这个最干净）：

```cmd
winget uninstall Git.Git
winget uninstall Obsidian.Obsidian
winget uninstall OpenJS.NodeJS.LTS    ← 仅当你自己装过 Node
```

⚠️ 用第三方卸载工具卸 Obsidian 时，**不要勾选「删除用户数据 / 应用数据」**，那会连笔记库一起删。

### 令牌不会自动清掉

部署时令牌写进了 Windows 凭据管理器（条目名 `git:https://github.com`），卸载 git 或 Obsidian 不会删除它。
想清除：控制面板 → 凭据管理器 → Windows 凭据 → 找到 `git:https://github.com` → 删除。

### 卸载后如何恢复发布

1. 重装 Git（必须）
2. 打开 Obsidian → 侧边栏 ↑ 图标上传一篇笔记，验证推送是否正常
3. 若提示认证失败：在命令行执行一次 `git push`，按提示输入 GitHub 用户名和令牌（令牌会被重新存进凭据管理器）

## 自检

```powershell
.\GardenDeployer.exe --selftest
```

不弹窗口，直接检查「界面资源能否加载、69 个控件是否齐全、Node/Git/Obsidian 是否能探测到、模板目录是否找到」，
结果写到 `%TEMP%\garden-selftest.txt`。**首次拿到 exe 建议先跑一次**。

## 排错

- **build.bat 报编译错误**：把控制台输出发我，逐条改（没在这台机器上编译过，第一次可能需要修几处）
- **双击没反应**：UAC 被拒绝时程序不会启动；右键 → 以管理员身份运行
- **Node/Git 装完仍显示未安装**：程序会自动刷新 PATH；若仍失败，手动安装后点「重新检测」
- **推送失败 401/403**：令牌缺 `repo` / `workflow` 权限，重新生成
- **推送失败 404**：仓库名被占用，换一个
- **Pages 没自动开启**：仓库 Settings → Pages → Source 选 "GitHub Actions"
- **插件没自动启用**：Obsidian 设置 → 第三方插件 → 关闭安全模式后手动启用 Blog Uploader
- 崩溃日志：`%TEMP%\garden-deployer-error.log`

## 源码结构

```
deployer/
├── build.bat            一行命令编译出 exe
├── src/
│   ├── Program.cs       入口、资源加载、--selftest
│   ├── Shell.cs         窗口逻辑：输入、按钮、日志、进度、步骤状态
│   ├── Engine.cs        部署引擎：探测、安装、构建、GitHub API、插件
│   ├── ui.xaml          界面布局（深色青蓝仪表风格，编译进 exe 作为资源）
│   └── app.ico          图标（由 tools/make-icon.js 生成）
├── tools/make-icon.js   重新生成图标：node tools/make-icon.js
└── _fallback-ps1/       PowerShell 版（引擎已实测跑通，exe 编译不通过时的备用方案）
```

技术约束：系统自带的 `csc` 只支持 **C# 5**，所以代码里没有字符串插值、`?.`、`nameof` 这类新语法。
